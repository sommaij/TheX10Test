# เอกสารออกแบบระบบ (Design Document)

## 1. เป้าหมาย

รับ **เสียงร้องเปล่า** (เสียงร้องล้วน ไม่มีดนตรีประกอบ) แล้วผลิต:
1. **ดนตรีประกอบ** ที่เข้ากับเสียงร้อง (ตรงคีย์ + จังหวะ)
2. **เพลงมิกซ์สมบูรณ์** ที่รวมเสียงร้อง + ดนตรี พร้อมปรับคีย์ให้เข้ากัน

## 2. สถาปัตยกรรม

ระบบแบ่งเป็น 4 ขั้นตอนที่ *แยกความรับผิดชอบชัดเจน* (แต่ละขั้นเปลี่ยน implementation
ได้อิสระ):

### ① Analysis — วิเคราะห์เสียงร้อง (`analysis.py`)
- **คีย์**: คำนวณ chroma (CQT) เฉลี่ยตลอดคลิป แล้ว correlate กับโปรไฟล์
  Krumhansl-Schmuckler ทั้ง 24 คีย์ (12 tonic × major/minor) เลือกคีย์คะแนนสูงสุด
  พร้อมค่าความมั่นใจ
- **จังหวะ (BPM)**: `librosa.beat.beat_track` จาก onset envelope
- **ช่วงเสียง**: `librosa.pyin` หา f0 กลาง เพื่อเลือกออกเทฟของคอร์ด/เบสให้อยู่ "ใต้"
  เสียงร้อง ไม่ตีกับเมโลดี้

### ② Arrangement — เรียบเรียง (`theory.py`, `arranger.py`)
- `theory.py` เป็นแกนทฤษฎีดนตรี: แปลงคีย์ → สเกล → คอร์ดไดอะโทนิก → คอร์ดโปรเกรสชัน
  ยอดนิยม (I–V–vi–IV ฯลฯ)
- `arranger.py` วางเลเยอร์: **แพด** (คอร์ดค้าง), **เบส** (root), **พลัค** (อาร์เพจจิโอ),
  **กลอง** (kick/snare/hihat) ให้ตรง BPM แล้ววนคอร์ดคลุมความยาวเสียงร้อง
- ผลลัพธ์เป็น `Note` (start, duration, pitch, velocity, instrument) — เป็นตัวแทนกลาง
  ที่ **ไม่ผูกกับ backend เสียง**

### ③ Synthesis — สังเคราะห์เสียง (`synth.py`)
- ซินธ์ pure-NumPy: ออสซิลเลเตอร์ (saw/sine) + ADSR + สังเคราะห์กลอง
- เลือกแนวนี้เพื่อให้ **รันได้ทันทีไม่ต้องมี soundfont/GPU/โมเดล**
- **จุดต่อขยาย**: `render_arrangement(arr, sr)` คืน `np.ndarray` สามารถแทนที่ด้วย
  backend อื่นได้ทั้งก้อน เช่น
  - เรนเดอร์ `Note` เป็น MIDI แล้วส่งเข้า soundfont (FluidSynth)
  - ส่ง prompt (คีย์ + BPM + สไตล์ + คอร์ด) เข้าโมเดล generate ดนตรี
    (MusicGen / Stable Audio / Riffusion) แล้วรับ waveform กลับมา

### ④ Mixing — มิกซ์ + ปรับคีย์ (`mixer.py`)
- **ปรับคีย์**: `librosa.effects.pitch_shift` เลื่อนเสียงร้องเป็นจำนวน semitone
  - ปกติดนตรีถูกสร้างในคีย์ของเสียงร้องอยู่แล้ว → ไม่ต้องเลื่อน
  - ถ้าผู้ใช้ระบุ `--target-key` ระบบจะเรียบเรียงดนตรีในคีย์ใหม่ แล้ว *เลื่อนเสียงร้อง
    ให้ตาม* (เลือกทิศทางที่ใกล้สุด ±6 semitone)
- **มิกซ์**: บาลานซ์ระดับเสียงร้อง/ดนตรี, reverb แบบ feedback-delay ให้เสียงร้องมีมิติ,
  จับความยาวสองแทร็กให้เท่ากัน, ลิมิตเตอร์กันคลิป

## 3. เหตุผลการออกแบบ (Design Rationale)

| ประเด็น | ทางเลือก | เหตุผล |
|---|---|---|
| Backend เสียง | ซินธ์ NumPy ในตัว | รันได้ทุกเครื่องทันที ไม่ต้องโหลดโมเดลหนัก และเป็น baseline ที่วัดผลได้ |
| ตัวแทนกลาง | `Note` events | สลับ synth ↔ โมเดล AI โดยไม่แตะ analysis/mix |
| ตรวจคีย์ | Krumhansl-Schmuckler | มาตรฐาน, ทนต่อ timbre ของเสียงร้อง, ให้ค่าความมั่นใจได้ |
| เรียบเรียง | ทฤษฎีดนตรี (rule-based) | คุมได้ว่าเข้าคีย์แน่นอน ไม่หลุดคีย์แบบโมเดลสุ่ม |

## 4. แนวทางต่อยอด

1. **เมโลดี้ตาม**: ให้เบส/พลัคเดินตาม contour ของ f0 จาก pYIN แทนอาร์เพจจิโอคงที่
2. **โครงสร้างเพลง**: ตรวจ verse/chorus จากพลังงาน แล้วเปลี่ยน intensity ตามท่อน
3. **โมเดล generate จริง**: ต่อ MusicGen ผ่าน `render_arrangement` (ดูข้อ ③)
4. **จัดจังหวะเสียงร้อง**: time-stretch เสียงร้องให้ล็อกกับ grid ของ BPM
5. **สเตอริโอ + มาสเตอร์ริ่ง**: EQ, สเตอริโออิมเมจ, mastering chain

## 5. ข้อจำกัดปัจจุบัน

- สมมติจังหวะ 4/4 และ tempo คงที่
- ดนตรีเป็นแนว rule-based (ยังไม่ใช่โมเดล neural generate)
- เอาต์พุตเป็น mono
